# Как работает TrackFix

TrackFix — Android-приложение на Kotlin. Все вычисления выполняются на
устройстве, интернет не нужен. На вход принимаются GPX и FIT, результат
исправления и объединения всегда сохраняется в GPX, результат режима «Фото» —
PNG.

## Общая схема

```
GPX / FIT
   │
   ├─ GpxCodec ──────────────┐
   └─ FitCodec → GPX в памяти ┤
                              ▼
                    FixEngine / MergeEngine
                              │
                              ▼
                       GPX (исправление, объединение)

Фото + GPX/FIT → ActivityStatsCalculator → PhotoCardRenderer → PNG
```

## Чтение файлов

### GPX

GPX разбирается как XML DOM. Это позволяет сохранить структуру документа,
пространства имён и расширения (пульс, каденс, мощность, температуру и другие
поля), которые приложение не понимает. При записи результата существующие
узлы и атрибуты не пересоздаются без необходимости.

### FIT

FIT разбирается встроенным парсером:

- заголовок, определения сообщений и записи `record`;
- события старта/остановки и границы сегментов;
- сжатые отметки времени;
- developer-поля;
- сообщения с big-endian порядком байтов.

Из FIT в GPX в памяти переносятся координаты, время, высота, накопленная
дистанция, скорость, пульс, каденс, мощность и температура. Служебные
сообщения FIT и developer-поля в GPX не переносятся.

Максимальный размер входного файла — 30 МБ.

## Режим «Fix»

### Эталон

Эталонный трек превращается в набор полилиний. Для быстрого поиска ближайшей
точки используется пространственная сетка. Сегменты, разделённые авто-паузой,
склеиваются, если разрыв между ними не больше 100 м; это важно для записей,
где эталон состоит из нескольких кругов.

### Поиск проблемных точек

Проблемными считаются:

- точки без координат;
- точки, улетевшие далеко от эталона;
- участки с аномальными скачками скорости, если они одновременно далеко
  от эталона;
- «зависшие» участки: подряд идущие точки с одинаковыми координатами,
  хотя накопленная дистанция или скорость показывают движение.

Короткие остановки с нулевой скоростью не считаются зависанием GPS.

### Восстановление

Для проблемного участка ищутся надёжные опорные точки до и после него.
Координаты восстанавливаются вдоль эталона с учётом времени, накопленной
дистанции и выбора правильного круга или направления.

Для зависшего участка все точки равномерно распределяются по эталону между
опорными точками. Доля пути считается по накопленной дистанции, если она
монотонна, иначе по времени.

Пропуски GPS в начале и конце трека заполняются от ближайшей существующей
GPS-точки в сторону эталона. Новые точки не создаются: заполняются только
уже существующие отметки, у которых есть время или данные датчиков.

### Границы и реальные объезды

Участки на границе трека, которые просто выходят за пределы эталона,
намеренно не притягиваются обратно. Плавный участок, который уходит в сторону
от эталона и затем возвращается (реальный обход, другая полоса), остаётся
на месте, если на его краю нет подозрительного скачка скорости.

### Трек без GPS

Если в исходном файле нет ни одной корректной координаты, `FixEngine`
передаёт обработку в `NoGpsReconstructor`. Обычное сопоставление точек с
эталоном здесь невозможно, поэтому маршрут строится целиком:

1. Берётся самый длинный путь эталона. Если в эталоне несколько несвязанных
   путей, выводится предупреждение о сегментах.
2. Для каждой точки определяется, является ли она паузой: скорость не больше
   0,05 м/с, либо, если скорости нет, каденс не больше нуля.
3. Интервал между соседними точками считается движением, если хотя бы один
   из его концов не является паузой. Так короткая остановка не теряет время
   подхода к ней и выхода из неё.
4. Суммируется время всех подвижных интервалов. Средняя скорость равна
   полной длине эталона, делённой на это время.
5. Первая точка ставится в начало эталона. На каждом подвижном интервале
   позиция сдвигается вдоль эталона на `средняя скорость × длительность`.
   На паузе позиция не меняется. Последняя точка попадает в конец эталона.
6. Количество точек, порядок, время, пульс, каденс и существующая высота
   сохраняются. Отсутствующая высота при включённой настройке берётся из
   эталона.
7. Из восстановленного GPX удаляется накопленная дистанция `<distance>`:
   она относится к старой геометрии, и без её удаления Strava могла бы
   считать длину по старым значениям, а не по новым координатам.

Если все интервалы выглядят как пауза, восстановление невозможно: приложение
показывает сообщение о том, что в треке нет времени движения.

### Что не меняется

- количество точек;
- порядок точек;
- время;
- пульс, каденс, мощность, температура;
- существующая высота;
- расширения GPX и прочие данные (кроме устаревшей накопленной дистанции `<distance>` при восстановлении трека без GPS).

Отсутствующая высота заполняется из эталона только при включённой настройке.

### Ключевые параметры

| Параметр | Значение |
|---|---|
| Зависание GPS | не менее 3 подряд идущих точек, координаты меняются не более чем на 0,5 м |
| Подтверждение движения | накопленная дистанция ≥ 20 м, либо скорость ≥ 1,5 м/с и разница проекций ≥ 20 м, либо скорость ≥ 2 м/с и длительность ≥ 5 с |
| Для файлов без датчиков | длительность ≥ 15 с и разница проекций ≥ 50 м |
| Склейка сегментов эталона | разрыв ≤ 100 м |
| Пауза в треке без GPS | скорость ≤ 0,05 м/с; если скорости нет — каденс ≤ 0 |
| Допустимое отклонение | по умолчанию 30 м, настраивается от 10 до 100 м |

## Режим «Сложить»

1. Каждый файл разбирается тем же кодеком, что и в режиме «Fix».
2. Файлы сортируются по первому времени. Первый файл становится основой
   итогового документа.
3. Для каждого следующего файла отбрасывается начало, время которого не позже
   максимального времени уже объединённой части. Полностью перекрытый файл
   пропускается и отмечается в предупреждении.
4. Все оставшиеся точки собираются в один `<trk>`, но каждый непустой сегмент
   исходного файла становится отдельным `<trkseg>`. Полностью обрезанные
   сегменты в результат не попадают.
5. Из точек удаляется устаревшая накопленная дистанция `<distance>`: в каждом
   исходном файле она начинается с нуля, и если оставить старые значения,
   Strava и подобные сервисы показывают дистанцию только одного файла.
   Дистанция в сводке и в принимающих сервисах считается по координатам.
6. Расширения и объявления пространств имён сохраняются; результат всегда GPX.

Файл без единой отметки времени отклоняется: без времени нельзя определить
его место в общей хронологии.

## Режим «Фото»

### Статистика

- Время без пауз суммируется только по интервалам не длиннее 30 секунд, где
  скорость не ниже 0,5 м/с; разрывы между сегментами не учитываются.
- Дистанция суммируется по координатам внутри сегментов, без соединительных
  отрезков между ними.
- Средний темп и средняя скорость рассчитываются по времени без пауз, если
  пройдено не меньше 100 м.
- Средний пульс и средняя мощность берутся по точкам, где соответствующий
  датчик присутствует.
- Общий подъём суммирует только перепады высоты от 2 м, чтобы не накапливать
  шум.

### Загрузка фотографии

`PhotoLoader` читает содержимое URI один раз в байты. Сначала определяется
размер изображения, затем оно декодируется с уменьшением до 1600 px по большей
стороне. Учитывается EXIF-ориентация. При нехватке памяти включаются резервные
варианты декодирования с меньшим размером. Исходный файл не изменяется.

### Отрисовка карточки

`PhotoCardRenderer` сохраняет пропорции снимка и рисует:

- заголовок «ТРЕНИРОВКА»;
- выбранный тип тренировки: маленький белый значок бегуна или велосипедиста
  либо пользовательский текст;
- дату тренировки справа;
- выбранные показатели в одну или две колонки.

Панели, рамки, затемняющего градиента и акцентной полоски нет: на фотографии
остаётся только текст. Читаемость на светлом и тёмном фоне обеспечивает
мягкая чёрная тень под каждой строкой. Размеры шрифтов и отступов вычисляются
от размера фотографии. Если показателей много и содержимое не помещается,
шрифты автоматически уменьшаются. Значок типа тренировки масштабируется с
сохранением пропорций и по высоте сопоставим со строкой заголовка. Если
собственная подпись слишком длинная, она уменьшается, чтобы не выйти за
пределы снимка.

Выбор «Бег», «Вело» или «Своё» и пользовательский текст сохраняются
в `SharedPreferences`, поэтому остаются при следующем запуске. Для своего
варианта доступно до 24 символов; пустой текст не выводится.

### Сохранение и отправка

PNG сохраняется через системный диалог `CreateDocument` либо передаётся
в другое приложение через `FileProvider` и `ACTION_SEND`. Разрешения на
доступ к галерее приложению не нужны: пользователь сам выбирает файл через
системный диалог.

## Тесты и сборка

Требования: JDK 17, Android SDK 35. Путь к SDK укажите в `local.properties`.

```powershell
.\gradlew.bat :app:testDebugUnitTest
.\gradlew.bat :app:lintRelease
.\gradlew.bat :app:assembleRelease
```

Часть тестов использует реальные GPX- и FIT-файлы из
`app/src/test/resources`. Эти файлы не публикуются, потому что содержат
личные маршруты. Без них соответствующие тесты помечаются как пропущенные;
синтетические тесты кодеков и алгоритмов выполняются всегда.

С реальными файлами проверяются исправление зависших и пропущенных координат,
сохранение точек, времени и датчиков, объединение GPX/FIT, сегменты и удаление
устаревшей дистанции, расчёты статистики для режима «Фото», а также
восстановление трека без GPS по эталону: удержание пауз, сохранение датчиков,
удаление `<distance>` и совпадение длины с эталоном.

## Структура кода

| Файл | Назначение |
|---|---|
| `MainActivity.kt` | экран, вкладки, выбор файлов, исправление и объединение |
| `PhotoShareController.kt` | режим «Фото»: трек, тип тренировки, показатели, предпросмотр, сохранение и отправка |
| `PhotoCardRenderer.kt` | отрисовка заголовка, показателей и значка/подписи поверх фото |
| `PhotoLoader.kt` | чтение фотографии, EXIF, уменьшение и резервное декодирование |
| `core/GpxCodec.kt` | разбор, изменение и запись GPX |
| `core/FitCodec.kt` | разбор FIT и преобразование в GPX |
| `core/ReferencePath.kt` | эталонная полилиния и пространственная сетка |
| `core/TrackFixer.kt` | поиск и исправление проблемных участков |
| `core/NoGpsReconstructor.kt` | восстановление маршрута без GPS по эталону |
| `core/FixEngine.kt` | оркестрация обработки файла |
| `core/MergeEngine.kt` | хронологическое объединение треков |
| `core/ActivityStats.kt` | статистика тренировки для режима «Фото» |
